# 行为契约

本文档是用户可见行为的权威说明。实现变化若影响界面、默认值、存储或模型请求，必须同步更新
本文档与 [`README.md`](../README.md)、[`README.en.md`](../README.en.md)。

## 适用范围

- 支持 DeepSeek Harness ≥ 0.1.2-rc.1。完整浏览器增强运行在 `web`；一次性无头任务使用 `headless` profile，需单独安装本 bundle。
- profile 共用 `${DSH_HOME:-~/.dsh}/settings.yaml`，所以无头模式遵循 Web 已保存的 `dsh-zh` Host 设置；它没有 Client，浏览器增强不进入无头模式。
- 无头模式没有额外日志约束；本插件处理自己的提示注入、DSH 官方工具/上下文，以及
  「网络搜索」的后端接管与 agent 作用域工具壳（headless profile 需单独安装本 bundle，
  详见「网络搜索」章）。
- 本版本词典与 locale 契约按 DSH 0.1.2-rc.1 对齐，更旧的 DSH 上中文补全部分条目会失配。
- Node.js 要求：`^22.19.0 || >=24.0.0`。
- 中文补全只在 Web 中文界面生效；其余 Web 界面增强在中文和英文界面都生效，只受各自开关控制，文案随界面语言切换。
- 提示词注入只受自身开关控制，与界面语言无关，默认关闭。
- 代理角色提示中文化、工具说明中文化与上下文注入中文化只受各自开关控制，与界面语言无关，默认关闭，只作用于新会话（老会话不重新注入）。

## 中文补全

中文补全不会做任意页面翻译，只处理已知词典键和经过确认的硬编码文本：

1. `ZH`：必须整句重写的少量模板。
2. `ZH_PARTIAL` + `TERMS`：只替换上游原句中的目标术语，句子其余部分继续跟随上游。
3. 参数格式化：把时长、吞吐量和词元数量转换成中文格式。
4. DOM 文本层：只对已知整段文本或已知动态格式做精确/正则匹配，不改正文片段。

按「键名」跨命名空间兜底的通用词表（`ZH['*']`）**只在上游值不含中文时生效**：
`empty`/`error`/`status` 这类通用键名在多个命名空间里都是整句，兜底若不判上游是否已本地化，
就会把整句压成一个词（2026-09-23 修复前：`settings.plugins.empty`「本部署没有开放任何插件
视图。」被压成「空」）。

界面采用以下已确认术语；其中部分由插件改写，部分直接沿用上游中文：

| 原文 | 中文 |
| --- | --- |
| token / tok | 词元 |
| tok/s | 词元/秒 |
| LLM | 大模型 |
| TTFT | 首词元时间 |
| API Key / API key | 接口密钥 |
| Model ID | 模型标识 |
| agent / subagent | 代理 / 子代理 |
| plan mode | 计划模式 |
| Agent Team（团队动作按钮） | 代理团队 |

> 「代理团队」是**刻意**保留的用户偏好：上游官方插件卡把同一功能叫「智能体团队」，
> 本插件只译团队动作按钮上的英文 `Agent Team`，**不改动上游已有的「智能体团队」**。
> 同一功能存在两个中文名是预期状态（用户 2026-09-23 明确要求），不要当成不一致去「统一」。

`subagent → 子代理` 直接沿用上游中文；权限预设内置标签（仅可查看 / 可写入工作区 / 完全权限）与
confirm 文案自 0.1.2-alpha.2 起由上游本地化，本插件不再覆盖（跟随上游叫法），
只保留 host 下发的权限描述与斜杠命令说明改写；其余术语主要由 locale 补丁处理。
保留 Cordis、DeepSeek、TypeScript、命令名、文件名、快捷键和示例标识符。数量格式使用万和亿：
`12.2K → 1.22万`、`46.7M → 4670万`、`123.4M → 1.234亿`。时长示例：
`48m48s → 48分48秒`、`2.4s → 2.4秒`。

**插件页与「智能体团队」按钮的文案属数据层**：官方插件卡片标题（`data-plugin-item="agent-loop"`
→「Agent 循环」）、卡片一句话描述（`plugins.item` 槽位 summary，如「控制 Agent 派发工具调用的
方式。」）、卡片标题按钮的 `aria-label`（「查看 Subagent」）以及团队动作按钮
（`data-team-action` 内的「Agent Team」）**都不在任何 locale 词典里**——它们由各官方插件以
数据形式提供（DSH 0.1.7 起插件配置表单由 schemastery `Config` 自动投影）。因此这类文案
**只能走 DOM 文本层的整段精确改写**（`dom-labels.ts` 的 `PLUGIN_ITEM_LABELS`），
`ZH`/`ZH_PARTIAL` 词典补丁对它们无效。原文以真实 GUI 的 DOM 快照为准，上游改字后需同步。

刻意保留的上游行为：

- `hint.goal.active` 中的 goal action 提示保持上游文本。
- Models 中 K/M 输入提示保持上游单位。
- 上游 0.1.2 已把 code 预设改名为 PTC 模式并补全中文（`presetPtcName`/`presetPtcDescription`）；
  按用户要求，本插件以整句覆盖把这两个键改为自定义叫法「程序模式」，描述中的
  「PTC 模式 SDK」同步译作「程序模式开发包」，不随上游措辞变化。
- plan 提示保留 `(/plan off)` 命令信息。
- trajectory 工具栏词典自 0.1.2-alpha.2 起由上游完整本地化（时长 / 展开所有轮次 等），
  本插件不再覆盖 trajectory 命名空间。
- 回答末尾的用量/耗时统计（TurnUsagePanel）由上游词典提供中文，模板中残留的
  `tok`/`token` 单元由本插件术语统一为「词元」；用量 pill 里的 `2.4M`/`15.8K` 缩写
  同步转为「240万」/「1.58万」，详细面板的精确计数（如 `2,400,000`）保持千分位原样。

## DOM 增强边界

中文补全的 DOM 文本层仅中文界面处理以下已知区域：

- 权限预设的 host 下发描述（内置标签自 0.1.2-alpha.2 起上游已本地化，不再改写）；
- `/compact`、`/goal`、`/feedback`、`/plan`、`/permission`、`/export` 的菜单说明；
- 斜杠菜单「技能来源」里 DSH 官方 shipped 技能的描述（`editing-cordis-compositions`、
  `cordis-plugin-development`，来自随部署分发的 SKILL.md frontmatter；用户自建技能
  不收录、原样保留）；
- 聊天区状态、工具行标题和轨迹视图标签；
- Models 设置页由提示词 settings 暴露产生的内部提供方目录行。

聊天统计行与流式思考 DisclosureRow 是布局/交互增强，中文和英文界面都按各自开关生效。

普通 DOM 变化只扫描新增或变化子树；设置或语言变化时全量重放。切换英文时，中文补全
的文本改写按反向表还原；关闭对应开关或卸载插件时，插件会恢复文本、样式、隐藏状态、
自动展开状态以及被折叠的思考正文。

## 代理角色提示中文化与工具说明中文化

两个独立开关（`zhAgentPrompt` 代理角色提示中文化、`zhToolDesc` 工具说明中文化），
默认关闭，存于 `settings.yaml` 命名空间 `dsh-zh`，与界面语言无关（同「提示词注入」）。
开启后只改写**发往模型的请求内容**，不写会话历史、不注册模型工具：

- `zhAgentPrompt`：四个默认代理（standard / ptc / minimal / cordis）在组装后按精确英文原文换成中文；保留 `{{model}}` / `{{cwd}}` 等动态占位符，自定义 persona 不匹配则原样保留。
  同时替换系统级官方段落：`harness:identity`、`harness:source`、`app:web-surface`、`context:file-reference`、`ui:deliverable-file-references`。
- `zhToolDesc`：注入模型请求的工具说明按工具名替换为**DSH 官方工具**的中文版本，同时把
    system prompt 里的官方工具指引段落（`tool:*` sections）替换为中文。段落覆盖：
    `tool:read` / `tool:write` / `tool:edit` / `tool:glob` / `tool:grep` / `tool:pwsh` /
    `tool:jobs` / `tool:pty` / `tool:lsp` / `tool:web_search` / `tool:web_fetch` /
    `tool:goal` / `tool:ralph` / `tool:subagent` / `tool:subagent_fork` / `tool:workflow` /
    `tool:session-query` / `tool:structured_output` / `mcp-resource-servers`（MCP 服务器
    名字列表按分段替换，运行时数据原样保留）/ `team:policy`（Agent Teams 的协作策略，
    Lead 与 teammate 各注册一份；2026-09-23 补齐，此前被误判为第三方段落而整段英文）、
    `plan:policy`（计划模式
    策略；该文本来自 preset 配置，仅与 shipped 原文逐字一致才替换，复制后改写过
    的自定义 preset 不受影响；非计划模式下该 section 为空、原样保留不注入）、
    `tools:ptc-only`（PTC 模式的执行器收敛声明，非 PTC 会话为空段、不注入）与
    `tools:sdk`（PTC 模式「Writing code for run_code」段落：TS/Python 两个渲染器的
    固定说明模板分段替换为中文，生成的 SDK 代码声明保留英文，见「已知限制」）。
    工具名与参数名保持不变。**只覆盖 DSH 系统自己的工具**：段落与工具描述都带官方
    特征片段守卫（`TOOL_MATCH` / `TOOL_FLAVOR_DESC_ZH` / `match`）；第三方插件在
    Agent 作用域注册的同名阴影——hashline 替换的 `tool:read`/`tool:edit`、智谱替换的
    `tool:web_search`、以及本插件网络搜索功能注册的 `web_search` 工具壳与
    `tool:web_search` section——描述的是另一套机制、不含官方特征片段，因此保持原样，
    不会被按名盖回内置旧版。判定标准是「**由谁注册**」，与包名是否含 `experimental`
    无关：`team:policy` 由官方包 `@deepseek-ai/dsh-experimental-tool-agent-team` 注册，
    因此收录。同一工具名的多种官方描述逐 flavor 翻译：极简模式的
    persistent `pwsh`/`bash`（包默认与 preset 覆盖两套文本）、`str_replace_editor`
    默认描述、PTC 模式 `run_code` 的 TypeScript/Python 两语言描述；Agent Teams 的
    `send_message`/`list_agents`/`interrupt_agent` 与 subagent-control 的内置工具
    **重名但描述不同**，也走 flavor 分派，Team 会话与子代理会话各取对应译文。
    实测覆盖 standard / ptc / minimal 与 cordis；上述官方段落均按匹配规则换中文；minimal 的 complete persona 仍只含中文 persona。

**新会话生效、老会话不重新注入**：以会话是否产生过模型输出（`assistant/message`）
判定新旧。会话首次模型请求时按当前开关状态锁定语言（中文或英文），锁定后开关翻转
不再影响该会话：老会话永不改为中文，已锁定的新会话翻开关后保持中文。

实现方式：在 `systemPrompt.assemble` 返回后原地改写最终 assembly 的 persona 与工具
说明（complete persona 的 preset 同样生效）；开关全关或设置服务不可用时零改动。
任何改写失败只告警一次并返回原内容，不阻断模型请求。

## 上下文注入中文化
开关 `zhContextInject`（默认关闭，`settings.yaml` 命名空间 `dsh-zh`，与界面语言无关）。
与前两个中文化开关「只改写发往模型的请求内容」不同，本开关是**注入源头替换**：
DSH 注入会话的官方英文上下文在 `agent/pre-step` 阶段、进入会话历史之前被换成中文，
因此 GUI 上下文卡片、会话日志与模型请求三处一致显示中文。中文文本会持久化进
会话日志；关闭开关后新注入恢复英文，已写入的部分按官方行为保留。

覆盖范围（只处理 DSH 官方注入，用户消息与第三方插件消息绝不动；未匹配的模板行
与整块未知文本原样保留英文）：

- **工作区指令帧**（`<system-reminder>` 包裹的 AGENTS.md/CLAUDE.md 注入）：引入句、
  基线替换句、空基线句、截断提示句、`Instructions from:` / `Additional instructions
  from:` / `Instructions removed:` / `Updated instructions from:` 行及其说明句、
  字节预算标记（含 omitted/truncated 明细）。指令文件正文是用户内容，保留原文。
- **skill 目录帧**：首句、目录更新句、尾部两段说明、空目录与替换目录的全部说明句。
  目录条目行（skill 名称与描述）是作者内容，保留原文。
- **运行时上下文**（经 systemPrompt contexts 组装 + 头部行）：文件策略（read-only /
    workspace-write / danger-full-access，动态工作区路径保留）、审批策略（ask / never）、
    子代理委派声明，以及快照头部行与清空行（翻译代价见下）。未收录的未来 context 保持英文。
- **审批策略切换通知**：`The approval policy changed from …`（策略名 ask/never 保留）。
- **压缩检查点前言**（会话历史中的 replacement 消息）。`<compacted-summary>` 标签与
    摘要正文保留。
- **计划模式切换通知**：进入计划模式 / 切回默认模式两句。
- **动态 Cordis 插件通知**：激活成功 / 被拒绝 / 失败、手动运行结果、Client UI / Host
    handler / guard 失败通知的框架句（错误详情、`currentPackageId:` 等字段行保留原文）。
- **@pluginId 引用注入**（创作模式）：引用可用与不可用两种模板的全部指导句
    （`<cordis_dynamic_plugin_context>` 标签与内嵌 JSON 保留）。
- **定时提醒注入**：两条不可信提醒内容说明句（`[SCHEDULE REMINDER]` 标记与
    `*_json:` 字段行保留）。

**已知限制与代价**：运行时上下文的头部行（`Current runtime context. This snapshot
supersedes …` 及其清空变体）由 agent-loop 硬编码拼接，官方渲染侧永远是英文；本开关
按行级规则翻译它，代价是快照投影的 retained 比较每步失配、DSH 每步注入一条替换
快照（surface 替换语义，模型输入不膨胀，但会话日志每步多一条快照事件）。tmux
终端上下文快照同理且有 per-turn 重注入代价，不在覆盖范围；`<available_skills>`
目录条目（skill 名称与描述）、`<skill_content>` 正文、指令文件（AGENTS.md 等）
正文、压缩摘要正文、标题生成等辅助调用的内部指令均为作者/用户/程序内容，
按设计不翻译。

**生效语义**：与前两个开关共用会话语言锁定（regime）——会话首次请求时按当前开关
状态锁定，老会话永远保持英文，锁定后翻转开关不影响该会话；regime 表为进程内存，
进程重启后重建（重启前已锁定的中文会话继续按官方行为携带历史中的中文注入，新注入
回到当时的开关状态）。实现方式：pre-step 监听以 `prepend: true` 注册在监听链头部
（先执行，`next()` 返回的 decision 已包含核心注入器的消息，翻译后返回）+ 共享
assemble 管线改写 contexts 正文；任何改写失败只告警一次并沿用原文，不阻断模型请求。

## 网络搜索

由「网络搜索」开关（`zhWebSearch`，`settings.yaml` 命名空间 `dsh-zh`，**默认开**，
实时生效）控制。开启后本插件为 DSH 提供对话中的网络搜索能力，包含两个层面，
均不引入任何第三方运行时依赖（只用 Node 内置 https，TLS 层调成 Chrome 浏览器
指纹风格）：

**1. 搜索后端接管（web seam provider）**：向官方 web 服务注册组合 provider
`dsh-zh-web`，并把官方 web 实例的后端选择（`searchProviderId`）切到它；关闭开关
或卸载插件时恢复接管前的原值（原值可能是官方 `deepseek-official`，也可能是智谱
`zhipu-web-search-prime`，按安装环境如实恢复，非硬编码）。组合 provider 每次搜索
按以下级联挑选后端：

- **智谱优先**：智谱插件（`deepseek-harness-zhipu_plan_tools`，provider id
  `zhipu-web-search-prime`）已注册且可用时优先走智谱（两插件共存时的联动路径，
  顺序无关、搜索时动态判定）；
- **智谱失败自动转多引擎后端**：智谱搜索失败——含敏感内容过滤
  （`ZHIPU_CONTENT_FILTERED`）与网络/凭据失败——对同一查询自动转多引擎后端重试；
  用户主动中止（AbortError）不降级、直接上抛；
- **Key 型引擎层（可选，Tavily）**：凭据里配了 `TAVILY_API_KEY` 时优先走 Tavily
  官方 API（`Authorization: Bearer`，`search_depth: basic` = 1 点额度；结果取正文
  片段并截到 500 字符），命中即返回、不再触免 Key 引擎。未配置时**静默跳过**
  （不记失败，避免「没填 key」被报成搜索故障）；额度耗尽/限流（HTTP 429/432）
  记 1 小时退避并降级到免 Key 引擎，搜索不会因此整体失败；
- **设置页入口**：多引擎开关与 Key 同在「网络搜索」收缩卡片里（开关原为平铺行，
  已移入卡内）。卡内可填 Tavily API Key，经 `GET|POST /dsh-zh/api/search-credential`
  写入 `$DSH_HOME/.credentials.yaml` 的 `refs.TAVILY_API_KEY`；凭据每次调用现查，
  **保存即生效、无需重启**。界面只显示脱敏提示（前 8 + … + 后 4），明文不落
  localStorage、不进日志；环境变量提供的 Key 优先于凭据文件，此时「清除」按钮禁用
  （改不了已运行进程的环境变量）；
- **免 Key 多引擎级联（学习 Hermes 的 ddgs 元搜索架构）**：DuckDuckGo html
  端点 POST → lite 端点（主引擎，全进程排队串行）→ Yandex + Bing + Wikipedia
  opensearch API（并发兜底、聚合去重；合并顺序即优先级）。传输层以 Chrome 风格的
  cipher/sigalgs/ecdhCurve 发起请求；确认限流后记入 60 秒限流记忆（窗口内跳过 DDG
  直接兜底）。
  **DDG 的 HTTP 202 反爬是 IP + 请求量限流，不是 TLS 指纹问题**（2026-09-23 受控
  复测：primp 随机浏览器指纹、primp chrome、Node 默认 Agent、本 Chrome Agent 四者
  同一时段同样 202；短时间 1–2 次请求后整段 202），因此 DDG 只作「尽力而为」的
  主引擎，真正扛住可用性的是 Yandex/Bing。Hermes/ddgs 同样拿 202，只是它把非 200
  当「无结果」静默丢弃并聚合其它引擎，所以用户看不到该错误。
- **Yandex（无 Key）**：必须用**旧端点** `/search/site/?text=&web=1&searchid=<随机数>`
  （即 ddgs `engines/yandex.py` 用的那个）——`/search/?text=` 已被 captcha 墙接管
  （正文 title=Verification），而 `/search/site/` 仍返回真 SERP（2026-09-23 实测
  12 次请求 0 captcha、每页 10–14 条、中英文结果均沾边）。结果链接是**真实 URL**
  （跳转只藏在 `onmousedown` 的 clck/jsredir 里），不需要 Bing 那样的 ck/a 解包；
  正文出现 captcha 标记时按**失败**归因而不是「无结果」，否则会把拦截误报成
  「查不到」。命中词用 `<b>` **逐字**包住中文（`<b>深</b><b>圳</b>`），所以剥标签
  必须用空串——换成空格会把「深圳」拆成「深 圳」，被 CJK 二元组闸门整批误杀。
- **Bing 双主机 × 双通道**：主机 `cn.bing.com` 优先、`www.bing.com` 次选（2026-09-23
  实测本机 IP 上 www 会对中文查询返回 10 条与查询完全无关的「投毒」结果、每次还
  不一样，cn 同一查询稳定沾边）；每台主机先走 RSS 结构化通道（`&format=rss`，
  体积约 4KB、link 为真实 URL），再走 HTML 结果页。HTML 通道的结果链接全部包进
  `bing.com/ck/a` 跳转（2026-09 改版），解析时解包还原真实 URL 并过滤广告。
- **相关性闸门**：Bing 的某通道返回结果整批与查询词元（拉丁词 + CJK 二元组）
  零重叠时视为投毒响应，丢弃该批结果并换通道；全通道都投毒时按「Bing 无结果」
  处理。Yandex 同样过闸门（整批零重叠时按「无结果」处理）。两者都不把无关链接
  当搜索结果交给模型。
- **失败归因聚合**：所有引擎都拿不到结果时，错误消息逐个列出各引擎的归因
  （`DuckDuckGo 触发反爬限流 (HTTP 202)；Yandex 无结果；Bing 无结果；Wikipedia 无结果`），
  不再只报最后一个错误——否则会把 DDG 的限流误报成全局故障。
- 免 Key 引擎零配置；Tavily 可选，只需在凭据里填 `TAVILY_API_KEY`（见「凭据与隐私」）。
  官方内置 deepseek-official provider 永远排最后（它消耗完整模型轮次）。

**2. agent 作用域 `web_search` 工具壳**：Web profile 的官方 `dsh-tool-web` 行被
禁用、agent preset 默认不暴露 web_search 时，仅切后端模型看不到工具。本插件在
每个**非极简** Agent 的自身作用域注册同名 `web_search` 工具（参数为 1–4 条
`queries` 数组并合并去重结果）与 `tool:web_search` 指引 section（order 110），
结果渲染官方 `card:'web'`/`kind:'search'` 搜索卡片，单次调用超时 45 秒；工具的
execute 走官方 web seam，因此自动获得上述后端级联与智谱联动。壳的描述与指引
文本随「提示词注入」开关（`zhPrompt`）选择中英文，实时切换。

**职责让位（与智谱插件的关系）**——智谱壳优先、zh_pro 补缺，零侵入不改智谱代码：

- 智谱插件包行存在于 Loader（挂载中或已挂载）→ 智谱壳是 `web_search` 工具壳的
  唯一 owner，本插件不注册壳、撤下已注册的壳，只保留后端接管（智谱壳的 execute
  同样走 web seam，联动对智谱壳同样生效）；
- Agent 继承视图里 `web_search` 已被占用：官方定义（含官方特征片段）→ 让位
  （官方壳走 web seam，联动已由后端接管达成）；智谱定义 → 让位；其它未知第三方
  定义 → 保守让位，绝不覆盖他人注册；本插件自己的壳 → 幂等跳过；
- 极简模式（minimal 预设）是双工具组合承诺，壳与智谱壳同样不注入其中；
- 智谱单独安装 → 智谱壳工作；zh_pro 单独安装 → 本插件补壳；两插件共存 →
  智谱壳工作、zh_pro 只做后端接管。职责切换在智谱热挂载/移除（profile manifest
  监听）、开关或语言变化（settings watch）、web 服务就绪与 agent 生命周期事件
  （`agent/created` / `agent/disposed` / `agent-preset/selected`）时收敛。

**已知限制**：

- 智谱在设置中翻转自身搜索开关后，已存活 Agent 的壳职责要等到下一次收敛时机
  （新会话、切换 preset、开关/语言变化或智谱热装卸）才重新评估；期间模型看到的
  壳可能有短暂滞后，功能不受影响（两种壳的 execute 都走 web seam，后端级联一致）。
- zh_pro 先于智谱热挂载进长跑进程的窗口内，智谱壳首次注册会与本插件已注册的壳
  撞名，智谱以错误级日志报告「注册冲突重试耗尽」后自愈（下次 agent 事件时本
  插件让位、智谱壳正常落位）；冷启动（两插件都在 profile bundles）无此窗口。
- DDG 反爬限流是常态而非偶发（本机 IP 上短时间 1–2 次请求后即整段 202，改客户端
  TLS 指纹无效）；触发后 60 秒限流记忆窗口内自动跳过 DDG，Yandex/Bing/Wikipedia
  兜底照常出结果，用户只在三者同时无结果时才会看到聚合后的错误。
  免 Key 引擎都是公开端点解析，结果质量与条数不及 API 类后端（每条查询向上游取
  约 10 条，4 条查询合并去重后最多 40 条来源）。
- **Tavily 额度消耗**：Key 型引擎层排在免 Key 引擎之前，因此配了 `TAVILY_API_KEY`
  后**每次搜索都会消耗 1 点额度**（免费 1000 次/月，basic 深度），命中即返回；
  用尽后自动降级到免 Key 引擎。若想只在免 Key 引擎全部失败时才动用 Tavily
  （省额度换质量），需要调整 `web-search.ts` 中 `freeSearch` 的层序。
- Yandex 的结果来自其自有索引、不经国内审核，因此同一中文查询在 Yandex 与
  cn.bing.com 上可能得到不同（含更敏感）的结果集；这是引擎属性而非插件行为。

## 提示词注入

提示词从设置变更后的后续模型请求开始生效，目标二选一：

- `system`：在 `systemPrompt.assemble` 返回后，把文本作为 `dsh-zh:language` section
  写入最终 system prompt，不产生可见上下文消息。
- `user`：不修改 system sections，在 `agent/pre-step` 插入一条来源为
  `deepseek-harness-zh_pro`、form 为 `notice` 的 `user/message`；聊天记录可展开查看全文。

旧值 `context` 读取时归一化为 `user`。文本框本地即时回显，静默 600ms 后写入 settings，
失焦时立即写入。开关关闭或文本为空时两条通道都不注入。

## 自动展开最新思考

- 流式思考出现时展开最新一条。
- 新思考出现时，只收起上一条由插件自动展开的内容。
- 流式结束后保留最后一条展开，历史会话不自动展开。
- DSH v0.1.2 起会话流默认以「紧凑」视图在每个已完成回答前折叠过程内容（含思考块），该折叠在轮次级生效且高于本插件的块级展开：自动展开在流式期间照常工作；回答完成后，最新思考随官方过程折叠一起隐藏，展开该轮折叠即可查看（插件展开状态保留）。把「对话显示」设为「标准」可恢复由本插件独自控制展开的旧行为。
- 关闭开关或卸载插件时恢复手动状态。

## 默认展开行数与展开模式

- 思考块展开后，正文超过 `thinkMaxLines`（默认 20）行时折叠为 N 行，显示方向由「折叠显示方向」决定：
  「最新 N 行」（默认）显示结尾、「最早 N 行」显示开头。
- 折叠用 **CSS 裁剪**（max-height + overflow + 滚动对齐），不改写正文文本：React 流式更新照常写入 DOM，
  折叠时可见行数随内容增长保持最新 N 行。
- 「展开模式」决定折叠后如何查看剩余内容：
  - **按钮模式**（默认）：折叠正文旁显示独占一行的「展开」按钮，位置随方向：最新 N 行时在正文上方
    （被折叠的更早内容在上方，向上追溯）、最早 N 行时在正文下方（向下展开后续行）；流式输出期间
    「最早 N 行」方向显示一行实时滚动的最新内容（正文固定在开头、看不到新输出），「最新 N 行」方向
    正文已跟随最新内容、不再显示。每次点击再多显示 N 行，直到全部展开后按钮消失；按钮文案带剩余
    行数提示，如「再展开 20 行（还有 60 行）」，剩余不足一批时变「展开全部（还有 N 行）」。展开后
    固定保持全文，后续会话继续、甚至用原版按钮反复折叠/展开都不会再重新折叠；插件不提供「收起」控件，
    收起交给思考块原版按钮。
  - **滚动模式**：正文限定为设置行数的高度并自带滚动条，用鼠标滚轮上下查看全文；没有「再展开」按钮
    与实时行。「折叠显示方向」决定初始位置：最新 N 行初始在底部、流式输出期间默认跟随底部（始终显示
    最新内容），用户向上滚动后暂停跟随、滚回底部恢复；最早 N 行初始在顶部（显示开头），位置完全交给
    用户滚动。
- 按钮模式下用户点过「再展开」后该思考块记住展开进度：即使流式继续增长、或用原版按钮收起再展开
  （正文被重挂），也不会缩回初始 N 行，而是保持已展开的行数（流式增长时仍只显示用户进度对应的最新
  行数）。只有改变「折叠显示方向」才重置进度。
- 流式输出期间点击「再展开」同样立即生效：展开基于正文当前（实时）内容计算，不会因缓存旧文本而回退。
- 折叠只作用于思考块正文，不影响 `自动展开最新思考` 的展开行为。
- `0` 表示不限制行数，此时不起作用。关闭开关或卸载插件时移除折叠样式，正文保持原文。

## 自动归档旧会话

点击左侧「新会话」并进入新会话界面（已选择工作区，此时 current 指向该工作区的
空白会话）后，自动把该工作区内超过 `zhAutoArchiveDays`（默认 7，范围 0–365）天
未活动的会话加入官方归档集合：会话从列表隐藏，日志与工作区归属原地保留。判定
依据是 `session.list` 的 `updatedAt`（创建时间与最近人工消息的较晚者）。运行中
（running）与空白（blank，官方列表已隐藏且会被新会话重用）的会话不参与。`0`
表示关闭自动归档。

自动归档使用官方 `workspace.archiveSession` 通道，与手动「归档会话」共用同一个
归档集合，不区分来源。每次打开新建会话界面都会重新评估，幂等，不重复归档。

归档发生时，页面顶部会短暂显示「有 N 个会话已归档」的提示条（与官方 Toast 同风格，
约 4 秒后自动消失）；本次没有会话满足条件时不显示。

## 查看已归档

由「查看已归档」开关（`archiveViewEnabled`，localStorage，默认开）控制，与「自动归档
旧会话」归入设置页同一功能组（自动归档在上、查看已归档在下）。**关闭时该功能完全不注册**：
不注入样式、不挂 MutationObserver、
不监听文档事件、不注册词典、不注入归档按钮，也不保留任何 DOM 副作用——不是简单隐藏
DOM。运行时翻转开关立即生效：关闭即卸载全部副作用（已注入的按钮、样式、归档行容器、
监听器全部移除），开启即重新注册。

开启时，每个工作区行（显示工作区实际名字的行）的行尾操作区（与官方「三点」和「新建会话」
按钮并列）新增两个图标按钮（中英文界面都显示，文案随界面语言切换）：**「全选」在最前，
「归档」紧随其后**（该工作区是否有可勾选会话由「会话多选」决定）：

- **「全选」按钮**（四宫格图标，位于「归档」按钮之前；「会话多选」关闭时不注入，
  开启时才显示）：点击一次**勾选该工作区当前视图下所有可勾选的会话**（正常列表 =
  该工作区分组下的官方空闲会话行；归档视图打开时 = 该工作区的归档行），再点一次
  **全部取消勾选**（toggle）。可勾选判定与多选一致：行内出现复选框才算可勾选（运行
  中、待交互、完成未读、blank 等行不勾）。按钮在当前视图所有可勾选会话都已选中时
  高亮（提示再点一次是取消）。操作只看当前视图的行，视图外的行不受影响；多选状态
  与官方行/归档行共用同一份。
- 点击**「归档」**按钮进入该工作区的归档视图 = **切换视图**：该工作区分组下的正常会话行被隐藏，
  归档会话行**顶替其位置直接出现在官方会话列表该分组内**（官方搜索/视图切换/
  工作区菜单等交互保持原生），是官方列表流的一部分——随官方列表**整体滚动（无
  独立滚动条）**，展开后整个列表变长；归档行随官方分组的展开/收起一并显示/隐藏。
  只显示属于该工作区的归档会话，按会话**最近活动时间（更新时间）降序**排序——与
  官方会话列表的 recency 语义一致，行尾「N 天前」按此排序不错位；刚活动/刚归档的
  会话排最前，一打开就能看到。默认显示 5 个；超过 5 个时显示「再展开 N 个归档」
  按钮，**渐进展开**：每点一次多显示 5 个（剩余不足 5 个时为剩余数；归档可能很多，
  一次性全展开会卡），全部展开后按钮变「收起」，再点收回 5 个。子代理（subagent）
  会话与 blank（未使用）会话不列入归档视图——官方列表对它们永不可见（子代理仅在
  其父会话目录中展示、blank 仅作为当前选中的临时「新会话」行），恢复后无从展示、
  点击必然表现为「会话消失」；
- 归档行与官方会话行观感一致：选中高亮；**标题与时间用 caption 灰**（对齐官方
  归档行的 `.sessionRow.archived .title/.time`，读作「不活跃」）；行尾有三点按钮
  （与官方会话行同位置：hover 显示、时间列让位），菜单 4 项——重命名（弹输入框，
  走 per-session rename 通道）、分叉会话（fork + 自动递增标题，成功后打开副本）、
  **取消归档**（官方菜单的「归档会话」对归档行反转为取消归档：行从归档列表消失、
  会话回到正常列表）、删除会话（红色危险项，与正常会话行三点菜单的删除项共用
  「会话删除按钮」开关和回收站路由，弹确认框）。「会话多选」开启且多选非空时，
  菜单追加批量项（项集随多选的归档构成变化，见「会话多选」章）；「批量删除」
  同样跟随「会话删除按钮」开关。菜单打开期间行保持高亮；Escape / 点击外部只关
  菜单，不退出归档视图。菜单卡片观感与官方三点菜单一致（同款半透明菜单底色 +
  背景模糊 + elevation 描边投影）；
- 该工作区没有归档会话时显示「暂无归档会话」；
- 点击归档行：静默取消归档并打开该会话（官方规则：归档会话必须先恢复才能打开，
  且归档中的会话不能保持为当前选中——「只打开不恢复」无法实现）。已打开的行
  **原位保留、外观不变**（仍是标题 + 相对时间，无任何标记），可连续点开多个会话
  浏览、列表零扰动；退出归档视图后再次进入，列表只含当前仍归档的会话。已打开的
  行再点一次等于重新打开；想把它放回归档，用正常列表该会话行三点菜单的官方
  「归档会话」；
- 退出方式：再点一次该工作区的归档按钮、按 Escape、点击该工作区「新建会话」按钮
  （会切到新会话界面）。点击页面其他任意区域**不会**退出归档视图，归档行持续显示，
  直到用户主动切回默认列表；
- 「未分组」会话桶同样注入归档按钮（该行没有官方「新建会话」按钮，归档按钮直接
  显示在行尾），点击查看不属于任何工作区的归档会话。

取消归档**优先走官方客户端 API** `workspaces.unarchiveSession`（走官方 RPC 并把
返回的完整归档集合 install 进客户端快照，因此归档集合与界面即时一致，不存在
「写入→follow 流回灌」的滞后窗口），与自动归档/手动「归档会话」共用同一个归档集合，
不区分来源。该 API 缺席（旧版宿主）时回退插件主机路由 `/dsh-zh/api/session.unarchive`：
宿主 workspaceRegistry 公开 unarchive API（DSH 2026-09-12 起）时直接走官方串行链，
归档集合与内存缓存即时同步、无需重启；更旧的宿主回退 storageDomain 直写（2026-09-24
修复 issue #8：`global.set` 是整体替换，直写必须保全量 state——此前只写
archivedSessionIds 单字段会冲掉 schema 必填字段，重启后 workspace 域校验失败、
dsh 无法启动），此路径下进程重启前官方列表可能仍按旧缓存把该会话过滤在归档中
（主机日志一次性提示 `workspace-unarchive-partial`）。

取消归档失败（官方 API 拒绝或路由返回失败）时不隐藏行，而是提示「取消归档失败：
{原因}」，不制造「行消失了、会话却没回来」的假成功。

归档行是注入官方列表流的纯 DOM 容器（不使用 React 槽位），挂在官方分组容器末尾；
官方重渲染瞬间或离开分组视图（如搜索展开）时容器先摘下、工作区行回来后自动挂回，
不退出归档视图。

## 删除会话（回收站）

会话列表行悬停出现的三点菜单中，额外提供「删除会话」项（危险样式，红色）。点击后
先显示确认框，确认后执行删除。**该菜单项在中文和英文界面都显示**，文案随界面语言
切换（中文「删除会话」/ 英文 Delete session）；由「会话删除按钮」开关控制是否显示。

**官方「显示已归档」视图的归档行同样提供该项**（2026-09-24 修复）：该行菜单的锚点
文案是「取消归档」而不是「归档会话」，此前按归档文案匹配会落空，已归档会话因此拿不到
删除入口——官方明确不做删除（「会话可以归档但绝不会被删除」），这是删除能力的唯一
盲区。现在锚点同时接受「归档会话」与「取消归档」两组文案（中英文各一对）。插件自建
归档视图的行菜单自带取消归档与删除项，会被显式跳过、不重复注入。

删除语义（与官方「归档会话」不同）：

- 日志移入系统回收站：会话日志目录（`~/.dsh/sessions/<项目>/<会话 id>/`）整体移入
  Windows 回收站 / macOS 废纸篓 / Linux XDG Trash，可从系统回收站手工还原文件；
- 不保留恢复位：同时调用官方 `Workspace.detachSession` 从工作区账本移除该会话槽位，
    因此删除后会话不再出现在会话列表、搜索或正常的归档视图结果中；即使从系统回收站还原目录，
  也只会被当作孤儿数据，不会自动恢复为会话；
- 运行中的会话拒绝删除（提示先停止或等待结束）——避免边写日志边移动文件；
  已打开但空闲（idle）的会话允许删除，包括当前正在查看的会话——删除前
  自动取消待处理消息并等待收敛（日志写盘完全由 `session/event` 驱动，
  空闲会话不会落盘，移走文件后不会「删除后复活」）；删除当前查看的会话
  成功后，客户端自动跳转到新会话页面；
- 驻留内存（live）的会话无法从 registry 卸载（上游没有按 id 卸载 live
  agent/session 的公开 API）。删除这类会话时自动把它加入官方归档集合
  （archivedSessionIds，官方语义：在所有分组不可见），保证删除后从列表
  消失；从回收站恢复时会自动取消归档并重新挂载工作区，会话重新可见。
  **从未驻留内存（冷）的会话删除后不触碰归档集合**：日志移走后官方列表
  的持久化数据源不再包含它，行自然消失——删除与「归档」是两个独立语义，
  删除入口绝不借用归档来假装删除。
  会话已从工作区账本与列表移除后，正常用户流程不会再次访问它。**已删除
  的会话不会出现在归档视图里**：归档视图按主机维护的「已删除集合」
  （`/dsh-zh/api/session.deleted`，删除成功全量回传、恢复成功移除，并与
  回收站清单取并集）把归档集合中的已删除项排除——否则上述「加入归档
  集合隐藏」的驻留会话会在归档视图里复活（2026-09 批量删除回归）。进程
  重启后已删除集合清空，但被删会话的摘要也随之消失，归档视图同样不再
  显示它们；归档集合（archivedSessionIds）中的死 id 会残留但无界面影响。
- **官方列表与搜索里的已删除会话行同样隐藏**（2026-09-25 修复）：官方归档
  集合只作用于「隐藏已归档」视图——视图切到「全部对话（显示已归档）」或
  「仅显示已归档」时，被删会话会作为灰色归档行重新出现，最典型的是掉进
  「未分组」桶（账本席位已随删除移除，它不再属于任何工作区）；官方内容搜索
  也会把它列出来。本插件按已删除集合给这些官方行打标记并用样式隐藏，行**不
  从 DOM 摘除**（行由 React 托管，外部移除会让下一次 reconcile 找不到节点），
  父级容器随之塌陷为 0 高、列表不留空位；某个分组若只剩被删会话则整个收起
  （官方「仅显示已归档」视图不会替我们丢掉空分组）。已删除集合为空时不打
  任何标记、不注入任何样式——没删过会话的界面与官方完全一致。从回收站恢复
  会话后集合同步移除该 id，标记与样式一并撤销、界面立即复原。

实现方式：客户端三点菜单注入 + 主机 `/dsh-zh/api` 路由（仅回环主机信任）。删除
成功后客户端刷新会话与工作区列表，行立即消失。被删除会话的清单保存在进程内存中
（进程重启后清单清空，属预期；回收站内容仍由操作系统管理）。已删除集合在
每次进程内首次查询时与官方归档集合对账自愈：归档 id 的日志无法读取
（`stat` 快照无结果或对应目录缺失）即判为已删除——活归档会话的日志必然在磁盘——
因此热更丢失内存态或历史残留的死 id 都能被重新识别，无需用户操作。

物理定位按 DSH 版本演进兼容（2026-09-07 起）：DSH 0.1.2-rc.1 用
`sessionPersistence.locate` 拿物理路径；0.1.3-alpha.1 起该公开面句柄化
（`readRaw`/`locate` 不再公开），改用 `stat` 快照的 header + 按
`~/.dsh/sessions/<项目>/<会话 id>/` 目录扫描定位。**定位失败或后端
类型无法移入回收站时，删除直接中止并报错（不改动任何数据）**——绝不
退化为「只移账本、日志留在原地」的假删除（否则会话会残留在官方列表的
「未分组」分组里，2026-09 实测定界）。

回收站清单（进程内）支持「恢复」：Windows 通过 Shell COM 定位回收站条目并移回
原路径（字节级还原）；macOS 从 `~/.Trash` 移回；Linux 按 XDG trashinfo 还原。
恢复后会话重新出现在列表（未分组，除非其工作区记录仍存在）。

已知限制：运行中的会话拒绝删除（提示先停止或等待结束）；日志目录无法定位或后端
类型不支持回收的会话**中止删除并报错**（不改动任何数据，可修复环境后重试）。

## 会话多选

由「会话多选」开关（`batchOpsEnabled`，localStorage，默认开）控制，中文和英文界面
都生效，文案随界面语言切换。

- **复选框**：官方会话行行首有一个状态 slot——运行中、待交互（等待批准/回答/计划
  审阅）、完成未读、子代理运行中的行会显示状态圆点图标，空闲会话的 slot 为空。
  鼠标悬停**空的 slot** 时出现复选框（悬停行首图标位；聚焦时同样显示），勾选后
  常显。有图标的行（运行中、待交互、完成未读）不出现复选框、不能多选；
  新会话占位（blank）行与快照里运行中的行同样不出现；工作区分组头行、搜索结果行
  不匹配会话行结构，天然排除。已勾选的会话若开始运行/被删除/变回占位，自动从
  多选中移除并摘除复选框。**归档视图中的归档行同样出现复选框**（slot 即归档行的
  行首占位，与官方行共用同一 `data-dsh-zh-batch-check` 标记与同一份多选状态）：
  勾选阻止冒泡、不触发行打开（取消归档 + 打开）；运行中的归档行不出现复选框。
- **全选按钮**：工作区行操作区最前（查看归档按钮之前，见「查看已归档」）有一个
  四宫格「全选」按钮（随「会话多选」开关显示/隐藏）。点击一次勾选该工作区**当前
  视图**下所有可勾选的会话（正常列表取官方空闲行、归档视图取归档行），再点一次
  全部取消；该工作区所有可勾选会话都已在多选中时按钮高亮。操作只看当前视图的行，
  多选状态与官方行/归档行同一份。
- **多选**：勾选状态是页面内存态，跨工作区分组生效；点击复选框不会打开会话
  （阻止冒泡）。平铺视图（groupBy flat）的空闲行官方不渲染行首 slot，无图标位
  可悬停，因此不出现复选框（分组视图不受影响）。
- **批量菜单**：多选非空时，点击任意会话行三点按钮，菜单在「归档会话」之后追加
  批量项。**提供哪些项由多选的归档构成决定**（`batchSelectionArchiveKind`）：
  - **全部未归档** → 「批量删除（N）」（危险样式）+「批量归档（N）」；
  - **全部已归档**（官方「显示已归档」视图里勾选）→ 「批量删除（N）」+
    「批量取消归档（N）」（已归档会话再归档无意义，恢复才有意义）；
  - **两类混选** → **只有「批量删除（N）」**：归档与取消归档都只对一半选中项成立，
    对另一半是反向操作，提供任一项都会误导。
  N 为当前多选数，官方菜单项原样保留。「批量删除」跟随「会话删除按钮」开关：该
  开关关闭时删除入口整体隐藏，多选菜单只保留归档方向那一项。**归档视图的归档行
  菜单**在多选非空时按同一规则追加批量项。多选状态与官方行同一份，跨正常列表/
  归档视图生效——正常列表勾选的会话也能在归档行菜单里被批量删除。
- **批量删除**：先弹确认框（说明日志移入系统回收站、不保留恢复位、运行中的会话
  会被跳过），确认后逐个串行调用主机 `/dsh-zh/api/session.delete`；全部成功提示
  「已删除 N 个会话」，部分失败提示「完成 X 个，失败 Y 个」及首个原因；若删除了
  当前查看的会话，跳转到新会话页面。完成后刷新列表并清空多选。
- **批量归档**：先弹确认框（可随时在归档视图中恢复），确认后逐个调用官方
  `archiveSession`（与手动/自动归档共用同一归档集合，不区分来源），完成后提示
  「已归档 N 个会话」、刷新列表并清空多选；运行中/占位行自动跳过并计入失败数。
- **批量取消归档**：先弹确认框，确认后逐个走**官方 `workspaces.unarchiveSession`**
  （与归档视图的单项/批量取消归档同一通道；旧版宿主缺该 API 时回退主机路由），
  完成后提示「已取消归档 N 个会话」、刷新列表并清空多选。
- 开关关闭时立即移除全部复选框并清空多选；卸载插件同样清理（样式、监听器、
  选择状态全部随 Fiber 释放）。

## 服务监控

设置页「服务监控」是与「对话样式相关」「对话列表相关」并列的独立收缩卡片（复刻官方插件设置卡样式：12px 圆角边框、头部两行标题/描述 + 旋转箭头、展开换背景，默认收起，折叠态记忆在 localStorage）：总开关、刷新间隔与自定义监控项都在卡片内。总开关（`serviceMonitorEnabled`，**默认关**——进程归属与定位目录按平台尽力而为，并非所有环境都可用，需要时显式开启）在中文和英文界面都生效；关闭时注销右栏 tab 类型（引导页无入口、openTab 拒绝），且主机本来就没有后台任务，零开销。开启时主机没有后台定时任务：网页每次拉取快照时对比扫描缓存年龄，超过网页设置的刷新间隔才重新扫描本机 TCP 监听端口（Windows `netstat`、Linux 优先 `ss` 回退 `netstat`、macOS `netstat`），与「基线」（面板开始工作后第一次扫描时已在监听的端口集合）对比；并发拉取共享同一次进行中的扫描：

- 面板以**双形态**呈现，共享同一份轮询快照：① **左侧边栏原位置**（会话列表与底部设置之间）的 DOM 注入面板——无服务时整体隐藏、rail 折叠时隐藏、被官方重挂挤出时自动重插（原行为完整保留）；② **右侧边栏 tab**（官方两阶段协议：阶段一 `sidebarRightTabs` 注册页面类型，阶段二 keyed 槽位 `sidebar.right.pane.tab` 按 id 分发正文）——开启后在右栏引导页（guide）出现「服务监控」入口胶囊（排在官方「文件」之后），空态显示提示不隐藏。tab 芯片标题与面板标题随界面语言切换。对话中启动的本地服务（基线之外新出现的监听端口，如 `127.0.0.1:81`）显示为：绿色圆点 + 地址:端口 + 存活时长（刚刚 / N 分钟 / N 小时 / N 天），按启动时间从新到旧排列。悬停（或键盘聚焦）在线条目时**按需查询**监听进程归属：首次悬停先显示「正在查询监听进程…」，主机解析完成后提示**原位替换**为归属内容——进程名（PID）、可执行文件完整路径、启动命令行；Windows 上 PID 4 的内核 http.sys 端点由主机按 `netsh http show servicestate view=requestq verbose=yes` 的注册 URL 反查挂靠进程，并标注「经 http.sys 内核队列定位」。点击在线且已定位到进程的条目，由主机在文件管理器中定位该进程文件所在目录（Windows `explorer /select`、macOS Finder 显示、Linux xdg-open 所在目录）；未定位到进程的条目不可点击。tab 正文是纯 DOM 面板（React 容器只负责生命周期）：多个会话各自打开时共享同一份轮询快照（服务监控是机器级事实，不是会话级）。
- **条目操作按钮（仅右栏 tab；左栏面板不提供）**：在线条目的存活时长后面有三个操作按钮（悬停或键盘聚焦条目时显示，触屏常显）：**排除监控**（点击即执行，无确认框）——把该端点重新放入基线：条目立即从监控列表消失、端口出现在 tab 底部「基线端口」区（可再点击恢复监控）；自定义监控项条目的「排除监控」= 从设置移除该项并放回基线端口（否则探活会让它复活）。**永久监控**（确认框「是否执行」）——把端口加入设置页「服务监控」的自定义监控项（localStorage），主机侧同时把端点放入基线，自动发现列表不再出现该条目；自定义项永不因基线规则隐藏、始终显示在线/离线状态，达成「永久监控」。同端口项已存在时提示重复。**终止进程**（确认框「是否执行」）——由主机用**普通权限**尝试终止监听进程（Windows `taskkill /F /PID`、macOS/Linux `kill` SIGTERM，均不提权）：确认框显示进程名与 PID，他人或系统进程可能因权限不足失败；未悬停解析过归属的条目先提示「请先悬停解析」；结果以页面顶部 toast 反馈（成功「已发送终止请求」/失败「终止失败」）。终止成功后条目随下一轮扫描自然消失（自动发现）或转为离线（自定义项）。
- 归属查询的缓存语义：查询一次即按监听端点缓存（自定义监控项与自动发现条目一致），再次悬停立即显示；服务停止监听后缓存清除，服务重现后下次悬停重新查询。解析命令失败（如权限不足）30 秒内同端点不重复发起，之后悬停自动重试。轮询、快照与点击路径不产生进程查询——查询只由悬停/聚焦触发，这是该功能唯一的进程枚举开销。
- 面板排序：自动发现条目（绿点 + 地址 + 存活时长，按启动时间从新到旧）排在**最上方**——新监控到的服务一出现即自动置顶；自定义在线条目排其后；离线的自定义条目自动沉底。面板头部显示计数徽标；左栏形态无服务时整体隐藏，右栏 tab 空态显示提示。最多显示 50 条。
- **左栏面板一屏最多 10 行**（2026-09-24 起）：超出部分不撑长侧栏，改为在列表内滚动——**滚轮可用，但不显示滚动条**（三套声明覆盖 Firefox `scrollbar-width`、旧 Edge `-ms-overflow-style`、WebKit/Blink 伪元素；滚动条会挤压行宽、在窄侧栏里很吵）。列表下方出现一个圆形**向下箭头**表示还有更多：点击向下翻一屏（每次约 9 行，留一行做视觉衔接）；滚到最后一行时箭头自动**翻转向上**，点击回到顶部。10 行以内不溢出时箭头不出现、面板高度随条目数自然收缩。该上限**只作用于左栏面板**，右栏 tab 仍撑满容器、不限行数（原行为）。
- 服务停止监听后条目消失；同一端口停止后再次监听按新条目记录（时长重新计算）。开关关闭时两形态同时拆卸（左栏面板移除、右栏注销类型；已打开的 tab 由官方按类型消失处理，用户手动关闭）；左栏 rail 折叠时面板隐藏，展开后恢复。
- 监控窗口 = 面板开始工作之后：第一次扫描时已在监听的端口（基线，如 DSH 自己的 3080）不显示；插件热重载后基线重建；页面关闭/不可见期间不扫描，重新打开页面后的第一次拉取（缓存已超龄）重建基线。开关开启期间轮询保持运行（tab 未打开也保持快照新鲜，打开即显示当前状态）。**右栏 tab 底部提供「基线端口」区**：列出基线内的端口（按端口升序，每次显示 10 个，「显示更多」追加一页），点击某个端口即把它移出基线、立即进入监控列表（标记来源为基线恢复，时长从恢复时刻起算）；左栏面板不提供该交互。
- 扫描失败（命令缺失/超时）保留上次数据并只告警一次，面板不闪断。
- 自定义监控项：设置页「服务监控」卡片里添加（添加行在列表上方：名字（可空）+ 地址，地址支持 `127.0.0.1:81` / `localhost:3000` / `[::1]:8080`，回车或点「添加」，新条目追加显示在卡片最下方，卡片高度随内容自适应）。**已添加的条目行内就是文本框**：名字和地址可随时修改，回车或失焦保存；地址无效时该行地址框标红并提示、不保存（保留原值与草稿）；删除按钮紧跟条目。每添加一项即常驻面板：在线绿点（悬停按需查询归属、点击定位进程目录；目标是本机监听时按最近扫描匹配，含通配监听 `0.0.0.0`/`[::]`，`localhost` 归一化，远程域名不归属）、离线灰点（不可点击），永不因基线规则隐藏；有名字只显示名字，无名字才显示地址。
- 刷新间隔：`serviceMonitorIntervalSec`（默认 10 秒，范围 2–300）是**唯一的节奏设置**——网页把它随每次轮询带给主机，作为扫描缓存的允许年龄：距上次扫描超过它才重扫，否则直接返回缓存；修改即时生效（setTimeout 自循环）。自动发现条目的信息延迟 ≤ 一个刷新间隔；页面不可见时浏览器暂停轮询 = 完全零扫描。
- 平台与环境需求（归属/定位为尽力而为）：端口扫描与探活在 Windows / macOS / Linux 都可用——Windows `netstat` 内置，macOS `netstat` 内置，Linux 需 iproute2 的 `ss`（缺失时回退 net-tools 的 `netstat`，两者都没有则面板无数据）。悬停进程归属：Windows 用系统自带 PowerShell（需 PowerShell 3+/Win8+，`Get-CimInstance`），macOS 用系统 `ps`，Linux 读 `/proc`（仅当目标进程与 DSH 运行用户一致、或对 `/proc/<pid>` 有读权限时能取到名称/路径，否则显示「未定位到监听进程」）；PID 4 内核端点的 http.sys 反查（`netsh`）为 Windows 独有。点击定位进程目录：Windows `explorer /select`、macOS Finder 均内置可用，Linux 需桌面环境的 `xdg-open`。自定义监控项仅接受本机回环地址（`localhost` / `127.0.0.0/8` / `[::1]`）：设置页添加或修改地址时，非回环地址会被标红拒绝；历史遗留的非回环条目不发起 TCP 连接、恒显示为离线（探活不对非环回目标发起连接，避免被用作内网/公网扫描器），且不影响其余条目与快照返回。
- 数据流：浏览器按刷新间隔轮询 `POST /dsh-zh/api/service-monitor`（请求体携带自定义监控项与当前 `intervalSec`；主机对比扫描缓存年龄——超过间隔才重扫，否则返回缓存，再逐项探活自定义监控项：仅环回项发起 TCP connect，非环回项直接按离线返回，单项异常不拒绝整个请求；回环主机 + 同源信任围栏，与「删除会话」路由同一策略）；页面不可见时暂停轮询，回到前台下一轮补上。GET 同路径为调试入口（`?intervalSec=` 可选，缺省要求最新）。悬停走 `POST /dsh-zh/api/service-monitor/resolve` 按需解析并缓存归属；点击走 `POST /dsh-zh/api/service-monitor/open`，主机读取已缓存归属后执行平台 reveal 命令；路径永远来自主机进程枚举，不接受请求传入。条目操作走 `POST /dsh-zh/api/service-monitor/rebaseline`（排除监控；`persist:true` 时为「永久监控」主机半步）与 `POST /dsh-zh/api/service-monitor/kill`（普通权限终止，PID 来自已缓存归属，同样不接受请求传入）。不注册模型工具、不上传数据；自定义监控项只存浏览器 localStorage，不落主机磁盘。

## 数据与信任边界

- 不上传数据。模型工具注册仅限「网络搜索」的 agent 作用域 `web_search` 工具壳
  （经用户明确要求加入，随 `zhWebSearch` 开关装卸，注册面在 Agent own scope，
  卸载可逆）；除该工具壳外不注册任何模型工具。
- 除显式开启的提示词注入、代理角色提示中文化、工具说明中文化与上下文注入中文化外，
    不修改模型请求；前两者只改写发往模型的 system prompt 与工具说明，不写会话历史；
    上下文注入中文化替换 DSH 注入会话历史的官方英文文本（仅注入框架文本，用户消息、
    指令文件正文、skill 描述与第三方插件消息不动），关闭后新注入恢复英文，已写入会话的
    部分按官方行为保留。
  后两者只改写发往模型的 system prompt 与工具说明，不写会话历史。
- 网络搜索开关开启时，搜索查询会被发送到所选后端：智谱插件在场且可用时发往智谱
  （由智谱插件处理其凭据与回退）；配了 `TAVILY_API_KEY` 时发往 Tavily 官方 API
  （密钥只进 `Authorization` 请求头）；否则发往公开的 DuckDuckGo/Yandex/Bing/
  Wikipedia 端点。本插件不存储查询与结果，也不把密钥写入配置、日志或诊断快照；
  设置页「网络搜索」卡片是密钥**唯一**的落盘入口（写 DSH 凭据文件的 `refs` 段），
  界面与接口响应都只经手脱敏提示。
- 本地界面设置只写浏览器 localStorage。
- 提示词设置只经 DSH 官方 settings 服务写入 `settings.yaml`。
- 默认关闭提示词注入，关闭时没有额外 token 消耗。

## 已知限制

硬编码英文只覆盖内置清单。未收录文本和第三方插件内容保持原样，以避免误改用户正文。
PTC 模式的 `tools:sdk` 生成式 TypeScript/Python 工具目录（由上游 `dsh-tools` 渲染器生成，
PTC 会话中模型的唯一工具声明）中的**固定说明模板**（标题、首段、程序内说明、
bash 尾句、要点列表）已分段翻译为中文；**生成的代码声明块**（工具级 JSDoc/参数文档，
随每个版本与每个工具变化）按设计保留英文，整段追译成本高且极易失配（`tools:ptc-only`
的叙述性收敛声明仍翻译）。
后续方向是补充确认过的硬编码文本，并允许用户配置部分术语叫法。
