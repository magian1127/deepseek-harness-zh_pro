# 行为契约

本文档是用户可见行为的权威说明。实现变化若影响界面、默认值、存储或模型请求，必须同步更新
本文档与 [`README.md`](../README.md)、[`README.en.md`](../README.en.md)。

## 适用范围

- 支持 DeepSeek Harness ≥ 0.1.2-rc.1。完整浏览器增强运行在 `web`；Open Design 实际使用 `open-design` stdio profile，stock 一次性任务使用 `headless`，两者都需单独安装本 bundle。
- profile 共用 `${DSH_HOME:-~/.dsh}/settings.yaml`，所以两个短进程遵循 Web 已保存的 `dsh-zh` Host 设置；它们没有 Client，浏览器增强不进入 Open Design UI。
- `open-design` stdout 是严格 JSONL；Host 信息日志写 stderr。OpenDesign Charter 位于用户消息，不翻译；本插件只处理自己的提示注入、runtime persona、DSH 官方工具/上下文。
- 本版本词典与 locale 契约按 DSH 0.1.2-rc.1 对齐，更旧的 DSH 上中文补全部分条目会失配。
- Node.js 要求：`^22.19.0 || >=24.0.0`。
- 中文补全只在 Web 中文界面生效；其余 Web 界面增强在中文和英文界面都生效，只受各自开关控制，文案随界面语言切换。
- 提示词注入只受自身开关控制，与界面语言无关，默认关闭。
- 代理角色提示中文化、工具说明中文化与上下文注入中文化只受各自开关控制，与界面语言无关，默认关闭，只作用于新会话（老会话不重新注入）。

## 中文补全

中文补全不会做任意页面翻译，只处理已知词典键和经过确认的硬编码文本：

1. `ZH`：必须整句重写的少量模板。
2. `ZH_PARTIAL` + `TERMS`：只替换上游原句中的目标术语，句子其余部分继续跟随上游。
3. 参数格式化：把时长、吞吐量和词元数量转换成中文格式。
4. DOM 文本层：只对已知整段文本或已知动态格式做精确/正则匹配，不改正文片段。

界面采用以下已确认术语；其中部分由插件改写，部分直接沿用上游中文：

| 原文 | 中文 |
| --- | --- |
| token / tok | 词元 |
| tok/s | 词元/秒 |
| LLM | 大模型 |
| TTFT | 首词元时间 |
| API Key / API key | 接口密钥 |
| Model ID | 模型标识 |
| agent / subagent | 代理 / 子代理 |
| plan mode | 计划模式 |

`subagent → 子代理` 直接沿用上游中文；权限预设内置标签（仅可查看 / 可写入工作区 / 完全权限）与
confirm 文案自 0.1.2-alpha.2 起由上游本地化，本插件不再覆盖（跟随上游叫法），
只保留 host 下发的权限描述与斜杠命令说明改写；其余术语主要由 locale 补丁处理。
保留 Cordis、DeepSeek、TypeScript、命令名、文件名、快捷键和示例标识符。数量格式使用万和亿：
`12.2K → 1.22万`、`46.7M → 4670万`、`123.4M → 1.234亿`。时长示例：
`48m48s → 48分48秒`、`2.4s → 2.4秒`。

刻意保留的上游行为：

- `hint.goal.active` 中的 goal action 提示保持上游文本。
- Models 中 K/M 输入提示保持上游单位。
- 上游 0.1.2 已把 code 预设改名为 PTC 模式并补全中文（`presetPtcName`/`presetPtcDescription`）；
  按用户要求，本插件以整句覆盖把这两个键改为自定义叫法「程序模式」，描述中的
  「PTC 模式 SDK」同步译作「程序模式开发包」，不随上游措辞变化。
- plan 提示保留 `(/plan off)` 命令信息。
- trajectory 工具栏词典自 0.1.2-alpha.2 起由上游完整本地化（时长 / 展开所有轮次 等），
  本插件不再覆盖 trajectory 命名空间。
- 回答末尾的用量/耗时统计（TurnUsagePanel）由上游词典提供中文，模板中残留的
  `tok`/`token` 单元由本插件术语统一为「词元」；用量 pill 里的 `2.4M`/`15.8K` 缩写
  同步转为「240万」/「1.58万」，详细面板的精确计数（如 `2,400,000`）保持千分位原样。

## DOM 增强边界

中文补全的 DOM 文本层仅中文界面处理以下已知区域：

- 权限预设的 host 下发描述（内置标签自 0.1.2-alpha.2 起上游已本地化，不再改写）；
- `/compact`、`/goal`、`/feedback`、`/plan`、`/permission`、`/export` 的菜单说明；
- 斜杠菜单「技能来源」里 DSH 官方 shipped 技能的描述（`editing-cordis-compositions`、
  `cordis-plugin-development`，来自随部署分发的 SKILL.md frontmatter；用户自建技能
  不收录、原样保留）；
- 聊天区状态、工具行标题和轨迹视图标签；
- Models 设置页由提示词 settings 暴露产生的内部提供方目录行。

聊天统计行与流式思考 DisclosureRow 是布局/交互增强，中文和英文界面都按各自开关生效。

普通 DOM 变化只扫描新增或变化子树；设置或语言变化时全量重放。切换英文时，中文补全
的文本改写按反向表还原；关闭对应开关或卸载插件时，插件会恢复文本、样式、隐藏状态、
自动展开状态以及被折叠的思考正文。

## 代理角色提示中文化与工具说明中文化

两个独立开关（`zhAgentPrompt` 代理角色提示中文化、`zhToolDesc` 工具说明中文化），
默认关闭，存于 `settings.yaml` 命名空间 `dsh-zh`，与界面语言无关（同「提示词注入」）。
开启后只改写**发往模型的请求内容**，不写会话历史、不注册模型工具：

- `zhAgentPrompt`：四个默认代理（standard / ptc / minimal / cordis）以及 `@open-design/dsh-runtime` 的官方 `deployment:persona` 在组装后按精确英文原文换成中文；保留 `{{model}}` / `{{cwd}}` 等动态占位符，自定义 persona 不匹配则原样保留。
  同时替换系统级官方段落：`harness:identity`、`harness:source`、`app:web-surface`、`context:file-reference`、`ui:deliverable-file-references`。OpenDesign Charter 是应用放入 user message 的任务内容，不属于 persona，也不会被改写。
- `zhToolDesc`：注入模型请求的工具说明按工具名替换为**DSH 官方工具**的中文版本，同时把
    system prompt 里的官方工具指引段落（`tool:*` sections）替换为中文。段落覆盖：
    `tool:read` / `tool:write` / `tool:edit` / `tool:glob` / `tool:grep` / `tool:pwsh` /
    `tool:jobs` / `tool:web_search` / `tool:web_fetch` / `tool:goal` / `tool:ralph` /
    `tool:subagent` / `tool:subagent_fork` / `tool:workflow` / `tool:cordis`
    （创作模式的「Dynamic Cordis Plugins」整段指南）、`plan:policy`（计划模式
    策略；该文本来自 preset 配置，仅与 shipped 原文逐字一致才替换，复制后改写过
    的自定义 preset 不受影响；非计划模式下该 section 为空、原样保留不注入）、
    `tools:ptc-only`（PTC 模式的执行器收敛声明，非 PTC 会话为空段、不注入）与
    `tools:sdk`（PTC 模式「Writing code for run_code」段落：TS/Python 两个渲染器的
    固定说明模板分段替换为中文，生成的 SDK 代码声明保留英文，见「已知限制」）。
    工具名与参数名保持不变。**只覆盖 DSH 系统自己的工具**：段落与工具描述都带官方
    特征片段守卫（`TOOL_MATCH` / `TOOL_FLAVOR_DESC_ZH` / `match`）；第三方插件在
    Agent 作用域注册的同名阴影——hashline 替换的 `tool:read`/`tool:edit`、智谱替换的
    `tool:web_search`——描述的是另一套机制、不含官方特征片段，因此保持原样，
    不会被按名盖回内置旧版。同一工具名的多种官方描述逐 flavor 翻译：极简模式的
    persistent `pwsh`/`bash`（包默认与 preset 覆盖两套文本）、`str_replace_editor`
    默认描述、PTC 模式 `run_code` 的 TypeScript/Python 两语言描述。
    实测覆盖 standard / ptc / minimal / cordis 与 Open Design runtime persona；上述官方段落均按匹配规则换中文；minimal 的 complete persona 仍只含中文 persona。

**新会话生效、老会话不重新注入**：以会话是否产生过模型输出（`assistant/message`）
判定新旧。会话首次模型请求时按当前开关状态锁定语言（中文或英文），锁定后开关翻转
不再影响该会话：老会话永不改为中文，已锁定的新会话翻开关后保持中文。

实现方式：在 `systemPrompt.assemble` 返回后原地改写最终 assembly 的 persona 与工具
说明（complete persona 的 preset 同样生效）；开关全关或设置服务不可用时零改动。
任何改写失败只告警一次并返回原内容，不阻断模型请求。

## 上下文注入中文化
开关 `zhContextInject`（默认关闭，`settings.yaml` 命名空间 `dsh-zh`，与界面语言无关）。
与前两个中文化开关「只改写发往模型的请求内容」不同，本开关是**注入源头替换**：
DSH 注入会话的官方英文上下文在 `agent/pre-step` 阶段、进入会话历史之前被换成中文，
因此 GUI 上下文卡片、会话日志与模型请求三处一致显示中文。中文文本会持久化进
会话日志；关闭开关后新注入恢复英文，已写入的部分按官方行为保留。

覆盖范围（只处理 DSH 官方注入，用户消息与第三方插件消息绝不动；未匹配的模板行
与整块未知文本原样保留英文）：

- **工作区指令帧**（`<system-reminder>` 包裹的 AGENTS.md/CLAUDE.md 注入）：引入句、
  基线替换句、空基线句、截断提示句、`Instructions from:` / `Additional instructions
  from:` / `Instructions removed:` / `Updated instructions from:` 行及其说明句、
  字节预算标记（含 omitted/truncated 明细）。指令文件正文是用户内容，保留原文。
- **skill 目录帧**：首句、目录更新句、尾部两段说明、空目录与替换目录的全部说明句。
  目录条目行（skill 名称与描述）是作者内容，保留原文。
- **运行时上下文**（经 systemPrompt contexts 组装 + 头部行）：文件策略（read-only /
    workspace-write / danger-full-access，动态工作区路径保留）、审批策略（ask / never）、
    子代理委派声明，以及快照头部行与清空行（翻译代价见下）。未收录的未来 context 保持英文。
- **审批策略切换通知**：`The approval policy changed from …`（策略名 ask/never 保留）。
- **压缩检查点前言**（会话历史中的 replacement 消息）。`<compacted-summary>` 标签与
    摘要正文保留。
- **计划模式切换通知**：进入计划模式 / 切回默认模式两句。
- **动态 Cordis 插件通知**：激活成功 / 被拒绝 / 失败、手动运行结果、Client UI / Host
    handler / guard 失败通知的框架句（错误详情、`currentPackageId:` 等字段行保留原文）。
- **@pluginId 引用注入**（创作模式）：引用可用与不可用两种模板的全部指导句
    （`<cordis_dynamic_plugin_context>` 标签与内嵌 JSON 保留）。
- **定时提醒注入**：两条不可信提醒内容说明句（`[SCHEDULE REMINDER]` 标记与
    `*_json:` 字段行保留）。

**已知限制与代价**：运行时上下文的头部行（`Current runtime context. This snapshot
supersedes …` 及其清空变体）由 agent-loop 硬编码拼接，官方渲染侧永远是英文；本开关
按行级规则翻译它，代价是快照投影的 retained 比较每步失配、DSH 每步注入一条替换
快照（surface 替换语义，模型输入不膨胀，但会话日志每步多一条快照事件）。tmux
终端上下文快照同理且有 per-turn 重注入代价，不在覆盖范围；`<available_skills>`
目录条目（skill 名称与描述）、`<skill_content>` 正文、指令文件（AGENTS.md 等）
正文、压缩摘要正文、标题生成等辅助调用的内部指令均为作者/用户/程序内容，
按设计不翻译。

**生效语义**：与前两个开关共用会话语言锁定（regime）——会话首次请求时按当前开关
状态锁定，老会话永远保持英文，锁定后翻转开关不影响该会话；regime 表为进程内存，
进程重启后重建（重启前已锁定的中文会话继续按官方行为携带历史中的中文注入，新注入
回到当时的开关状态）。实现方式：pre-step 监听以 `prepend: true` 注册在监听链头部
（先执行，`next()` 返回的 decision 已包含核心注入器的消息，翻译后返回）+ 共享
assemble 管线改写 contexts 正文；任何改写失败只告警一次并沿用原文，不阻断模型请求。

## 提示词注入

提示词从设置变更后的后续模型请求开始生效，目标二选一：

- `system`：在 `systemPrompt.assemble` 返回后，把文本作为 `dsh-zh:language` section
  写入最终 system prompt，不产生可见上下文消息。
- `user`：不修改 system sections，在 `agent/pre-step` 插入一条来源为
  `deepseek-harness-zh_pro`、form 为 `notice` 的 `user/message`；聊天记录可展开查看全文。

旧值 `context` 读取时归一化为 `user`。文本框本地即时回显，静默 600ms 后写入 settings，
失焦时立即写入。开关关闭或文本为空时两条通道都不注入。

## 自动展开最新思考

- 流式思考出现时展开最新一条。
- 新思考出现时，只收起上一条由插件自动展开的内容。
- 流式结束后保留最后一条展开，历史会话不自动展开。
- DSH v0.1.2 起会话流默认以「紧凑」视图在每个已完成回答前折叠过程内容（含思考块），该折叠在轮次级生效且高于本插件的块级展开：自动展开在流式期间照常工作；回答完成后，最新思考随官方过程折叠一起隐藏，展开该轮折叠即可查看（插件展开状态保留）。把「对话显示」设为「标准」可恢复由本插件独自控制展开的旧行为。
- 关闭开关或卸载插件时恢复手动状态。

## 默认展开行数与展开模式

- 思考块展开后，正文超过 `thinkMaxLines`（默认 20）行时折叠为 N 行，显示方向由「折叠显示方向」决定：
  「最新 N 行」（默认）显示结尾、「最早 N 行」显示开头。
- 折叠用 **CSS 裁剪**（max-height + overflow + 滚动对齐），不改写正文文本：React 流式更新照常写入 DOM，
  折叠时可见行数随内容增长保持最新 N 行。
- 「展开模式」决定折叠后如何查看剩余内容：
  - **按钮模式**（默认）：折叠正文旁显示独占一行的「展开」按钮，位置随方向：最新 N 行时在正文上方
    （被折叠的更早内容在上方，向上追溯）、最早 N 行时在正文下方（向下展开后续行）；流式输出期间
    「最早 N 行」方向显示一行实时滚动的最新内容（正文固定在开头、看不到新输出），「最新 N 行」方向
    正文已跟随最新内容、不再显示。每次点击再多显示 N 行，直到全部展开后按钮消失；按钮文案带剩余
    行数提示，如「再展开 20 行（还有 60 行）」，剩余不足一批时变「展开全部（还有 N 行）」。展开后
    固定保持全文，后续会话继续、甚至用原版按钮反复折叠/展开都不会再重新折叠；插件不提供「收起」控件，
    收起交给思考块原版按钮。
  - **滚动模式**：正文限定为设置行数的高度并自带滚动条，用鼠标滚轮上下查看全文；没有「再展开」按钮
    与实时行。「折叠显示方向」决定初始位置：最新 N 行初始在底部、流式输出期间默认跟随底部（始终显示
    最新内容），用户向上滚动后暂停跟随、滚回底部恢复；最早 N 行初始在顶部（显示开头），位置完全交给
    用户滚动。
- 按钮模式下用户点过「再展开」后该思考块记住展开进度：即使流式继续增长、或用原版按钮收起再展开
  （正文被重挂），也不会缩回初始 N 行，而是保持已展开的行数（流式增长时仍只显示用户进度对应的最新
  行数）。只有改变「折叠显示方向」才重置进度。
- 流式输出期间点击「再展开」同样立即生效：展开基于正文当前（实时）内容计算，不会因缓存旧文本而回退。
- 折叠只作用于思考块正文，不影响 `自动展开最新思考` 的展开行为。
- `0` 表示不限制行数，此时不起作用。关闭开关或卸载插件时移除折叠样式，正文保持原文。

## 统计全显示

匹配 StatsLine 的 `N 轮 · N 步`（中文界面）或 `N turns · N steps`（英文界面）计数组后：

- 保持单行，不使用省略号；
- 从 12px 开始自动缩小，最低 9px；
- 仍超长时启用横向滚动；
- 关闭开关或卸载插件时恢复上游样式。

## 自动归档旧会话

点击左侧「新会话」并进入新会话界面（已选择工作区，此时 current 指向该工作区的
空白会话）后，自动把该工作区内超过 `zhAutoArchiveDays`（默认 7，范围 0–365）天
未活动的会话加入官方归档集合：会话从列表隐藏，日志与工作区归属原地保留。判定
依据是 `session.list` 的 `updatedAt`（创建时间与最近人工消息的较晚者）。运行中
（running）与空白（blank，官方列表已隐藏且会被新会话重用）的会话不参与。`0`
表示关闭自动归档。

自动归档使用官方 `workspace.archiveSession` 通道，与手动「归档会话」共用同一个
归档集合，不区分来源。每次打开新建会话界面都会重新评估，幂等，不重复归档。

归档发生时，页面顶部会短暂显示「有 N 个会话已归档」的提示条（与官方 Toast 同风格，
约 4 秒后自动消失）；本次没有会话满足条件时不显示。

## 查看已归档

由「查看已归档」开关（`archiveViewEnabled`，localStorage，默认开）控制，与「自动归档
旧会话」归入设置页同一功能组（自动归档在上、查看已归档在下）。**关闭时该功能完全不注册**：
不注入样式、不挂 MutationObserver、
不监听文档事件、不注册词典、不注入归档按钮，也不保留任何 DOM 副作用——不是简单隐藏
DOM。运行时翻转开关立即生效：关闭即卸载全部副作用（已注入的按钮、样式、归档行容器、
监听器全部移除），开启即重新注册。

开启时，每个工作区行（显示工作区实际名字的行）的行尾操作区（与官方「三点」和「新建会话」
按钮并列）新增两个图标按钮（中英文界面都显示，文案随界面语言切换）：**「全选」在最前，
「归档」紧随其后**（该工作区是否有可勾选会话由「会话多选」决定）：

- **「全选」按钮**（四宫格图标，位于「归档」按钮之前；「会话多选」关闭时不注入，
  开启时才显示）：点击一次**勾选该工作区当前视图下所有可勾选的会话**（正常列表 =
  该工作区分组下的官方空闲会话行；归档视图打开时 = 该工作区的归档行），再点一次
  **全部取消勾选**（toggle）。可勾选判定与多选一致：行内出现复选框才算可勾选（运行
  中、待交互、完成未读、blank 等行不勾）。按钮在当前视图所有可勾选会话都已选中时
  高亮（提示再点一次是取消）。操作只看当前视图的行，视图外的行不受影响；多选状态
  与官方行/归档行共用同一份。
- 点击**「归档」**按钮进入该工作区的归档视图 = **切换视图**：该工作区分组下的正常会话行被隐藏，
  归档会话行**顶替其位置直接出现在官方会话列表该分组内**（官方搜索/视图切换/
  工作区菜单等交互保持原生），是官方列表流的一部分——随官方列表**整体滚动（无
  独立滚动条）**，展开后整个列表变长；归档行随官方分组的展开/收起一并显示/隐藏。
  只显示属于该工作区的归档会话，按会话**最近活动时间（更新时间）降序**排序——与
  官方会话列表的 recency 语义一致，行尾「N 天前」按此排序不错位；刚活动/刚归档的
  会话排最前，一打开就能看到。默认显示 5 个；超过 5 个时显示「再展开 N 个归档」
  按钮，**渐进展开**：每点一次多显示 5 个（剩余不足 5 个时为剩余数；归档可能很多，
  一次性全展开会卡），全部展开后按钮变「收起」，再点收回 5 个。子代理（subagent）
  会话与 blank（未使用）会话不列入归档视图——官方列表对它们永不可见（子代理仅在
  其父会话目录中展示、blank 仅作为当前选中的临时「新会话」行），恢复后无从展示、
  点击必然表现为「会话消失」；
- 归档行与官方会话行观感一致：选中高亮；行尾有三点按钮（与官方会话行同位置：
  hover 显示、时间列让位），菜单 4 项——重命名（弹输入框，走 per-session rename
  通道）、分叉会话（fork + 自动递增标题，成功后打开副本）、**取消归档**（官方菜单
  的「归档会话」对归档行反转为取消归档：行从归档列表消失、会话回到正常列表）、
  删除会话（红色危险项，与正常会话行三点菜单的删除项共用「会话删除按钮」开关和
  回收站路由，弹确认框）。「会话多选」开启且多选非空时，菜单在「删除会话」之后
  追加「批量取消归档（N）」与「批量删除（N）」（N 为当前多选数）；「批量删除」
  同样跟随「会话删除按钮」开关。菜单打开期间行保持高亮；Escape / 点击外部只关
  菜单，不退出归档视图；
- 该工作区没有归档会话时显示「暂无归档会话」；
- 点击归档行：静默取消归档并打开该会话（官方规则：归档会话必须先恢复才能打开，
  且归档中的会话不能保持为当前选中——「只打开不恢复」无法实现）。已打开的行
  **原位保留、外观不变**（仍是标题 + 相对时间，无任何标记），可连续点开多个会话
  浏览、列表零扰动；退出归档视图后再次进入，列表只含当前仍归档的会话。已打开的
  行再点一次等于重新打开；想把它放回归档，用正常列表该会话行三点菜单的官方
  「归档会话」；
- 退出方式：再点一次该工作区的归档按钮、按 Escape、点击该工作区「新建会话」按钮
  （会切到新会话界面）。点击页面其他任意区域**不会**退出归档视图，归档行持续显示，
  直到用户主动切回默认列表；
- 「未分组」会话桶同样注入归档按钮（该行没有官方「新建会话」按钮，归档按钮直接
  显示在行尾），点击查看不属于任何工作区的归档会话。

取消归档经主机 `/dsh-zh/api/session.unarchive` 路由改写官方归档集合
（archivedSessionIds），与自动归档/手动「归档会话」共用同一个归档集合，不区分来源。
workspaceRegistry 尚未公开 unarchive 或事务写 API，本插件只持久化归档集合、不私写其
内存缓存：取消归档的持久化即时生效，但进程重启前官方列表可能仍按旧缓存把该会话
过滤在归档中（主机日志一次性提示 `workspace-unarchive-partial`）；上游公开 API 后
恢复内存同步。

归档行是注入官方列表流的纯 DOM 容器（不使用 React 槽位），挂在官方分组容器末尾；
官方重渲染瞬间或离开分组视图（如搜索展开）时容器先摘下、工作区行回来后自动挂回，
不退出归档视图。

## 删除会话（回收站）

会话列表行悬停出现的三点菜单中，额外提供「删除会话」项（危险样式，红色）。点击后
先显示确认框，确认后执行删除。**该菜单项在中文和英文界面都显示**，文案随界面语言
切换（中文「删除会话」/ 英文 Delete session）；由「会话删除按钮」开关控制是否显示。

删除语义（与官方「归档会话」不同）：

- 日志移入系统回收站：会话日志目录（`~/.dsh/sessions/<项目>/<会话 id>/`）整体移入
  Windows 回收站 / macOS 废纸篓 / Linux XDG Trash，可从系统回收站手工还原文件；
- 不保留恢复位：同时调用官方 `Workspace.detachSession` 从工作区账本移除该会话槽位，
    因此删除后会话不再出现在会话列表、搜索或正常的归档视图结果中；即使从系统回收站还原目录，
  也只会被当作孤儿数据，不会自动恢复为会话；
- 运行中的会话拒绝删除（提示先停止或等待结束）——避免边写日志边移动文件；
  已打开但空闲（idle）的会话允许删除，包括当前正在查看的会话——删除前
  自动取消待处理消息并等待收敛（日志写盘完全由 `session/event` 驱动，
  空闲会话不会落盘，移走文件后不会「删除后复活」）；删除当前查看的会话
  成功后，客户端自动跳转到新会话页面；
- 驻留内存（live）的会话无法从 registry 卸载（上游没有按 id 卸载 live
  agent/session 的公开 API）。删除这类会话时自动把它加入官方归档集合
  （archivedSessionIds，官方语义：在所有分组不可见），保证删除后从列表
    消失；从回收站恢复时会自动取消归档并重新挂载工作区，会话重新可见。
    会话已从工作区账本与列表移除后，正常用户流程不会再次访问它。**已删除
    的会话不会出现在归档视图里**：归档视图按主机维护的「已删除集合」
    （`/dsh-zh/api/session.deleted`，删除成功全量回传、恢复成功移除，并与
    回收站清单取并集）把归档集合中的已删除项排除——否则上述「加入归档
    集合隐藏」的驻留会话会在归档视图里复活（2026-09 批量删除回归）。进程
    重启后已删除集合清空，但被删会话的摘要也随之消失，归档视图同样不再
    显示它们；归档集合（archivedSessionIds）中的死 id 会残留但无界面影响。
  会话已从工作区账本与列表移除后，正常用户流程不会再次访问它。

实现方式：客户端三点菜单注入 + 主机 `/dsh-zh/api` 路由（仅回环主机信任）。删除
成功后客户端刷新会话与工作区列表，行立即消失。被删除会话的清单保存在进程内存中
（进程重启后清单清空，属预期；回收站内容仍由操作系统管理）。已删除集合在
每次进程内首次查询时与官方归档集合对账自愈：归档 id 的日志无法读取
（readRaw 为空）即判为已删除——活归档会话的日志必然在磁盘——因此热更丢
失内存态或历史残留的死 id 都能被重新识别，无需用户操作。

回收站清单（进程内）支持「恢复」：Windows 通过 Shell COM 定位回收站条目并移回
原路径（字节级还原）；macOS 从 `~/.Trash` 移回；Linux 按 XDG trashinfo 还原。
恢复后会话重新出现在列表（未分组，除非其工作区记录仍存在）。

已知限制：运行中的会话拒绝删除（提示先停止或等待结束）；SQLite 等不提供日志
路径定位的后端只能逻辑删除（提示「无法回收」）。

## 会话多选

由「会话多选」开关（`batchOpsEnabled`，localStorage，默认开）控制，中文和英文界面
都生效，文案随界面语言切换。

- **复选框**：官方会话行行首有一个状态 slot——运行中、待交互（等待批准/回答/计划
  审阅）、完成未读、子代理运行中的行会显示状态圆点图标，空闲会话的 slot 为空。
  鼠标悬停**空的 slot** 时出现复选框（悬停行首图标位；聚焦时同样显示），勾选后
  常显。有图标的行（运行中、待交互、完成未读）不出现复选框、不能多选；
  新会话占位（blank）行与快照里运行中的行同样不出现；工作区分组头行、搜索结果行
  不匹配会话行结构，天然排除。已勾选的会话若开始运行/被删除/变回占位，自动从
  多选中移除并摘除复选框。**归档视图中的归档行同样出现复选框**（slot 即归档行的
  行首占位，与官方行共用同一 `data-dsh-zh-batch-check` 标记与同一份多选状态）：
  勾选阻止冒泡、不触发行打开（取消归档 + 打开）；运行中的归档行不出现复选框。
- **全选按钮**：工作区行操作区最前（查看归档按钮之前，见「查看已归档」）有一个
  四宫格「全选」按钮（随「会话多选」开关显示/隐藏）。点击一次勾选该工作区**当前
  视图**下所有可勾选的会话（正常列表取官方空闲行、归档视图取归档行），再点一次
  全部取消；该工作区所有可勾选会话都已在多选中时按钮高亮。操作只看当前视图的行，
  多选状态与官方行/归档行同一份。
- **多选**：勾选状态是页面内存态，跨工作区分组生效；点击复选框不会打开会话
  （阻止冒泡）。平铺视图（groupBy flat）的空闲行官方不渲染行首 slot，无图标位
  可悬停，因此不出现复选框（分组视图不受影响）。
- **批量菜单**：多选非空时，点击任意会话行三点按钮，菜单在「归档会话」之后追加
  两项——「批量删除（N）」（危险样式）与「批量归档（N）」（N 为当前多选数）。
  官方菜单项原样保留。「批量删除」跟随「会话删除按钮」开关：该开关关闭时删除
  入口整体隐藏，多选菜单只保留「批量归档」。**归档视图的归档行菜单**在多选非空
  时同样追加批量项，但语义不同：已归档会话本来就在归档集合中，「批量归档」无
  意义，因此提供「批量取消归档（N）」（确认后逐个恢复回正常列表，与手动恢复同
  一 unarchive 路由）与「批量删除（N）」（同样跟随「会话删除按钮」开关）。多选
  状态与官方行同一份，跨正常列表/归档视图生效——正常列表勾选的会话也能在归档行
  菜单里被批量删除。
- **批量删除**：先弹确认框（说明日志移入系统回收站、不保留恢复位、运行中的会话
  会被跳过），确认后逐个串行调用主机 `/dsh-zh/api/session.delete`；全部成功提示
  「已删除 N 个会话」，部分失败提示「完成 X 个，失败 Y 个」及首个原因；若删除了
  当前查看的会话，跳转到新会话页面。完成后刷新列表并清空多选。
- **批量归档**：先弹确认框（可随时在归档视图中恢复），确认后逐个调用官方
  `archiveSession`（与手动/自动归档共用同一归档集合，不区分来源），完成后提示
  「已归档 N 个会话」、刷新列表并清空多选；运行中/占位行自动跳过并计入失败数。
- 开关关闭时立即移除全部复选框并清空多选；卸载插件同样清理（样式、监听器、
  选择状态全部随 Fiber 释放）。

## 服务监控

设置页「服务监控」是与「对话样式相关」「对话列表相关」并列的独立收缩卡片（复刻官方插件设置卡样式：12px 圆角边框、头部两行标题/描述 + 旋转箭头、展开换背景，默认收起，折叠态记忆在 localStorage）：总开关、刷新间隔与自定义监控项都在卡片内。总开关（`serviceMonitorEnabled`，**默认关**——进程归属与定位目录按平台尽力而为，并非所有环境都可用，需要时显式开启）在中文和英文界面都生效；关闭时面板完全隐藏，且主机本来就没有后台任务，零开销。开启时主机没有后台定时任务：网页每次拉取快照时对比扫描缓存年龄，超过网页设置的刷新间隔才重新扫描本机 TCP 监听端口（Windows `netstat`、Linux 优先 `ss` 回退 `netstat`、macOS `netstat`），与「基线」（面板开始工作后第一次扫描时已在监听的端口集合）对比；并发拉取共享同一次进行中的扫描：

- 对话中启动的本地服务（基线之外新出现的监听端口，如 `127.0.0.1:81`）出现在左侧会话列表与底部设置之间的监控面板：绿色圆点 + 地址:端口 + 存活时长（刚刚 / N 分钟 / N 小时 / N 天），按启动时间从新到旧排列。悬停（或键盘聚焦）在线条目时**按需查询**监听进程归属：首次悬停先显示「正在查询监听进程…」，主机解析完成后提示**原位替换**为归属内容——进程名（PID）、可执行文件完整路径、启动命令行；Windows 上 PID 4 的内核 http.sys 端点由主机按 `netsh http show servicestate view=requestq verbose=yes` 的注册 URL 反查挂靠进程，并标注「经 http.sys 内核队列定位」。点击在线且已定位到进程的条目，由主机在文件管理器中定位该进程文件所在目录（Windows `explorer /select`、macOS Finder 显示、Linux xdg-open 所在目录）；未定位到进程的条目不可点击。
- 归属查询的缓存语义：查询一次即按监听端点缓存（自定义监控项与自动发现条目一致），再次悬停立即显示；服务停止监听后缓存清除，服务重现后下次悬停重新查询。解析命令失败（如权限不足）30 秒内同端点不重复发起，之后悬停自动重试。轮询、快照与点击路径不产生进程查询——查询只由悬停/聚焦触发，这是该功能唯一的进程枚举开销。
- 面板排序：自动发现条目（绿点 + 地址 + 存活时长，按启动时间从新到旧）排在**最上方**——新监控到的服务一出现即自动置顶；自定义在线条目排其后；离线的自定义条目自动沉底。面板（含「服务监控」标题与计数徽标）只在有服务时显示；无服务或全部停止后自动隐藏。最多显示 50 条。
- 服务停止监听后条目消失；同一端口停止后再次监听按新条目记录（时长重新计算）。
- 侧栏折叠为窄轨（rail）时面板隐藏，展开后恢复。
- 监控窗口 = 面板开始工作之后：第一次扫描时已在监听的端口（基线，如 DSH 自己的 3080）不显示；插件热重载后基线重建；页面关闭/不可见期间不扫描，重新打开页面后的第一次拉取（缓存已超龄）重建基线。
- 扫描失败（命令缺失/超时）保留上次数据并只告警一次，面板不闪断。
- 自定义监控项：设置页「服务监控」卡片里添加（添加行在列表上方：名字（可空）+ 地址，地址支持 `127.0.0.1:81` / `localhost:3000` / `[::1]:8080`，回车或点「添加」，新条目追加显示在卡片最下方，卡片高度随内容自适应）。**已添加的条目行内就是文本框**：名字和地址可随时修改，回车或失焦保存；地址无效时该行地址框标红并提示、不保存（保留原值与草稿）；删除按钮紧跟条目。每添加一项即常驻面板：在线绿点（悬停按需查询归属、点击定位进程目录；目标是本机监听时按最近扫描匹配，含通配监听 `0.0.0.0`/`[::]`，`localhost` 归一化，远程域名不归属）、离线灰点（不可点击），永不因基线规则隐藏；有名字只显示名字，无名字才显示地址。
- 刷新间隔：`serviceMonitorIntervalSec`（默认 10 秒，范围 2–300）是**唯一的节奏设置**——网页把它随每次轮询带给主机，作为扫描缓存的允许年龄：距上次扫描超过它才重扫，否则直接返回缓存；修改即时生效（setTimeout 自循环）。自动发现条目的信息延迟 ≤ 一个刷新间隔；页面不可见时浏览器暂停轮询 = 完全零扫描。
- 平台与环境需求（归属/定位为尽力而为）：端口扫描与探活在 Windows / macOS / Linux 都可用——Windows `netstat` 内置，macOS `netstat` 内置，Linux 需 iproute2 的 `ss`（缺失时回退 net-tools 的 `netstat`，两者都没有则面板无数据）。悬停进程归属：Windows 用系统自带 PowerShell（需 PowerShell 3+/Win8+，`Get-CimInstance`），macOS 用系统 `ps`，Linux 读 `/proc`（仅当目标进程与 DSH 运行用户一致、或对 `/proc/<pid>` 有读权限时能取到名称/路径，否则显示「未定位到监听进程」）；PID 4 内核端点的 http.sys 反查（`netsh`）为 Windows 独有。点击定位进程目录：Windows `explorer /select`、macOS Finder 均内置可用，Linux 需桌面环境的 `xdg-open`。自定义监控项仅接受本机回环地址（`localhost` / `127.0.0.0/8` / `[::1]`）：设置页添加或修改地址时，非回环地址会被标红拒绝；历史遗留的非回环条目不发起 TCP 连接、恒显示为离线（探活不对非环回目标发起连接，避免被用作内网/公网扫描器），且不影响其余条目与快照返回。
- 数据流：浏览器按刷新间隔轮询 `POST /dsh-zh/api/service-monitor`（请求体携带自定义监控项与当前 `intervalSec`；主机对比扫描缓存年龄——超过间隔才重扫，否则返回缓存，再逐项探活自定义监控项：仅环回项发起 TCP connect，非环回项直接按离线返回，单项异常不拒绝整个请求；回环主机 + 同源信任围栏，与「删除会话」路由同一策略）；页面不可见时暂停轮询，回到前台下一轮补上。GET 同路径为调试入口（`?intervalSec=` 可选，缺省要求最新）。悬停走 `POST /dsh-zh/api/service-monitor/resolve` 按需解析并缓存归属；点击走 `POST /dsh-zh/api/service-monitor/open`，主机读取已缓存归属后执行平台 reveal 命令；路径永远来自主机进程枚举，不接受请求传入。不注册模型工具、不上传数据；自定义监控项只存浏览器 localStorage，不落主机磁盘。

## 数据与信任边界

- 不注册模型工具，不上传数据。
- 除显式开启的提示词注入、代理角色提示中文化、工具说明中文化与上下文注入中文化外，
    不修改模型请求；前两者只改写发往模型的 system prompt 与工具说明，不写会话历史；
    上下文注入中文化替换 DSH 注入会话历史的官方英文文本（仅注入框架文本，用户消息、
    指令文件正文、skill 描述与第三方插件消息不动），关闭后新注入恢复英文，已写入会话的
    部分按官方行为保留。
  后两者只改写发往模型的 system prompt 与工具说明，不写会话历史。
- 本地界面设置只写浏览器 localStorage。
- 提示词设置只经 DSH 官方 settings 服务写入 `settings.yaml`。
- 默认关闭提示词注入，关闭时没有额外 token 消耗。

## 已知限制

硬编码英文只覆盖内置清单。未收录文本和第三方插件内容保持原样，以避免误改用户正文。
PTC 模式的 `tools:sdk` 生成式 TypeScript/Python 工具目录（由上游 `dsh-tools` 渲染器生成，
PTC 会话中模型的唯一工具声明）中的**固定说明模板**（标题、首段、程序内说明、
bash 尾句、要点列表）已分段翻译为中文；**生成的代码声明块**（工具级 JSDoc/参数文档，
随每个版本与每个工具变化）按设计保留英文，整段追译成本高且极易失配（`tools:ptc-only`
的叙述性收敛声明仍翻译）。
后续方向是补充确认过的硬编码文本，并允许用户配置部分术语叫法。
